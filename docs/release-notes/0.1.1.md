# 0.1.1 release notes (draft)

- `praxity doctor` now warns when T3's saved Praxity actions differ from a
  project's `t3.json`. This can explain why Open in Studio still opens the
  system browser after upgrading and running `praxity init`.
- When `praxity init` changes actions, it prints the same repair note as doctor:
  in T3's project Actions settings, delete each stale saved Praxity action and
  import it again from `t3.json`, or edit its saved command to match `t3.json`.

T3's import menu hides a same-name saved action even when its command changed.
Reset restores environment defaults rather than reloading `t3.json`. See
[T3 Code issue #18061](https://github.com/pingdotgg/t3code/issues/18061).

These checks read T3's settings and project mapping without changing them.
Optional JSON reads are bounded; the database and its committed WAL are queried
from a private snapshot, so doctor creates no live SQLite sidecars or locks.
Missing, unreadable, oversize or changing input is skipped.
